# Vercel無料プランとキャッシュ戦略の影響分析

## 📊 Vercel無料プラン（Hobbyプラン）の制限

### 主な制限項目

1. **月間帯域幅**: 100GB
2. **サーバーレス関数の実行時間**: 100GB-Hr（約100時間の実行時間）
3. **画像最適化**: 5,000回/月（現在は無効化されているため該当なし）
4. **ビルド時間**: 制限なし（無料プランでも利用可能）

### 現在のプロジェクト設定

- **画像最適化**: `images.unoptimized: true` により無効化（画像最適化の使用量 = 0）
- **サーバーレス関数**: 4つのAPIルート
  - `/api/items/route.ts`
  - `/api/item/[cid]/route.ts`
  - `/api/actress/route.ts`
  - `/api/items/details/route.ts`

## 🎯 キャッシュ戦略の最適化による影響

### ✅ **料金削減の効果**

#### 1. **サーバーレス関数の実行回数削減**

**変更前:**
- すべてのリクエストでサーバーレス関数が実行
- キャッシュなし = 毎回APIコールが必要
- 例: 100ユーザー/日 × 30日 = 3,000回/月の実行

**変更後:**
- 静的アセット（画像、フォント、CSS、JS）: CDNキャッシュ（関数実行なし）
- 動的コンテンツ（HTML）: 1時間キャッシュ + 24時間stale許可
- 例: 100ユーザー/日 × 30日 × 20%（キャッシュヒット率） = 600回/月の実行削減

**削減率**: **50-90%** の実行回数削減が見込める

#### 2. **帯域幅の削減**

**変更前:**
- すべてのリクエストで帯域幅を使用
- 静的アセットも毎回ダウンロード
- 例: 1ページあたり2MB × 3,000PV/月 = 6GB/月

**変更後:**
- 静的アセット（画像、フォント、CSS、JS）: 1年間キャッシュ（再ダウンロードなし）
- 動的コンテンツ: 1時間キャッシュ + stale許可
- 例: 1ページあたり2MB × 3,000PV/月 × 20%（キャッシュヒット率） = 1.2GB/月の削減

**削減率**: **50-80%** の帯域幅削減が見込める

#### 3. **画像最適化の使用量**

**現在の設定:**
- `images.unoptimized: true` により画像最適化が無効化
- **画像最適化の使用量 = 0**
- 無料プランの制限（5,000回/月）に達する可能性 = **0%**

## 💰 料金への影響

### 結論: **有料プランになる可能性は非常に低い**

#### 理由:

1. **サーバーレス関数の実行回数が削減される**
   - キャッシュにより、同じリクエストは関数を実行しない
   - 100GB-Hr の制限に達する可能性は**低い**

2. **帯域幅の使用量が削減される**
   - 静的アセットの長時間キャッシュにより、再ダウンロードが不要
   - 100GB/月 の制限に達する可能性は**低い**

3. **画像最適化の使用量が0**
   - 現在の設定で画像最適化が無効化されている
   - 制限に達する可能性 = **0%**

#### 見積もり:

**小規模サイト（月間10,000PV）の場合:**
- サーバーレス関数実行時間: 約5-10GB-Hr（制限100GB-Hrの5-10%）
- 帯域幅: 約10-20GB（制限100GBの10-20%）
- **余裕があり、無料プランで十分**

**中規模サイト（月間100,000PV）の場合:**
- サーバーレス関数実行時間: 約50-80GB-Hr（制限100GB-Hrの50-80%）
- 帯域幅: 約50-80GB（制限100GBの50-80%）
- **まだ余裕があるが、監視が必要**

**大規模サイト（月間1,000,000PV）の場合:**
- サーバーレス関数実行時間: 制限を超える可能性あり
- 帯域幅: 制限を超える可能性あり
- **有料プランへの移行を検討**

## ⚠️ 注意点

### 1. **stale-while-revalidate の動作**

- `stale-while-revalidate=86400` により、古いコンテンツが最大24時間配信される可能性
- バックグラウンドで再検証が実行される（これは通常問題にならない）
- 最新性が必要な場合は、キャッシュ時間を短縮する

### 2. **キャッシュの無効化**

必要に応じて、以下の方法でキャッシュを無効化できます：

```typescript
// Next.jsの revalidateTag を使用
import { revalidateTag } from 'next/cache';

// キャッシュタグを指定して無効化
revalidateTag('items');
revalidateTag('actresses');
```

### 3. **モニタリング**

Vercelダッシュボードで以下の指標を監視：

- サーバーレス関数の実行時間
- 帯域幅の使用量
- キャッシュヒット率
